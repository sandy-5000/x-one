For Week 1 — Java Language + Object Model, the goal should be to become extremely comfortable with the Java language itself before moving into Spring Boot, microservices, concurrency, or distributed systems.

Given your target of Java/Spring Boot backend roles at Apple, I’d structure this as a Java fundamentals + object-model deep dive + hands-on lab week, with emphasis on interview-level understanding rather than just syntax.

Week 1 — Java Language + Object Model

Week outcome

By the end of the week, you should be able to:

  • Write clean, idiomatic modern Java without relying on an IDE to explain the language.
  • Explain exactly how Java classes, objects, references, constructors, and inheritance work.
  • Understand stack vs heap, object lifetime, and garbage collection at a conceptual level.
  • Explain == vs equals(), hashCode(), and object identity.
  • Use interfaces, abstract classes, inheritance, composition, and polymorphism correctly.
  • Understand Java access modifiers and packages.
  • Explain static, final, this, super, and initialization order.
  • Understand Java's parameter-passing model.
  • Use exceptions properly.
  • Work comfortably with generics, enums, records, and nested classes.
  • Read unfamiliar Java code and reason about what it does.
  • Write unit tests for your Java code.
  • Complete a small Java-only lab project without Spring.

10. Java Parameter Passing

Very important for interviews.

Java is pass-by-value.

Even when passing objects.

Example:

void change(User user) {
    user.setName("Bob");
}

The reference itself is passed by value.

Understand this example:

void change(User user) {
    user = new User("Bob");
}

User user = new User("Alice");
change(user);

System.out.println(user.getName());

Why does it still print:

Alice

But:

void change(User user) {
    user.setName("Bob");
}

changes the object.

This distinction is extremely important.

12. Encapsulation

This is an important OOP principle.

Bad:

public class Account {
    public double balance;
}

Better:

public class Account {

    private double balance;

    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException();
        }

        balance += amount;
    }

    public double getBalance() {
        return balance;
    }
}

Understand:

  • hiding implementation details
  • protecting invariants
  • controlling state changes
  • API design

18. Method Overloading vs Overriding

Know this cold.

Overloading

Same class, same method name, different parameter list.

void print(int x)
void print(String x)

Resolved at compile time.

Overriding

Subclass provides implementation of inherited method.

@Override
public void execute() {
}

Resolved dynamically at runtime.

50. SOLID Principles

Learn these at a practical level.

S — Single Responsibility

A class should have a focused responsibility.

O — Open/Closed

Open for extension, closed for modification.

L — Liskov Substitution

Subtypes should behave appropriately when substituted for their base types.

I — Interface Segregation

Prefer focused interfaces.

D — Dependency Inversion

Depend on abstractions rather than concrete implementations.

The last one will become especially important when you start Spring dependency injection.

55. Repository Layer

Start with an in-memory implementation.

public interface ProductRepository {

    Optional<Product> findById(long id);

    List<Product> findAll();

    void save(Product product);
}

Then:

public class InMemoryProductRepository
        implements ProductRepository {

    private final Map<Long, Product> products =
        new HashMap<>();
}

This gives you an early taste of the abstraction style you'll later use with Spring.

The most important principle for this week is:

Don't learn Java as a collection of syntax rules. Learn how Java objects behave.

For the Apple-oriented preparation you're doing, that object-model foundation will pay off later when we get into Spring dependency injection → collections → concurrency → JVM → microservices → distributed systems. Week 1 should therefore be deliberately pure Java, with the lab forcing you to use the concepts rather than merely recognize them.
